02 / LEARN

Scope the work before adding features.

A build scope defines what you will create and exclude. A learning outcome explains why. Acceptance criteria define what must work; evidence criteria define what a later permitted test must reveal.

  1. Manually review the Validate decision and unresolved conditions.
  2. Choose one customer/task and learning assumption.
  3. Specify the minimum prototype/manual workflow and exclusions.
  4. Separate functional acceptance from customer evidence.
  5. Assign owners, dependencies and resource boundaries.
  6. Resolve safeguards before dependent execution.

Illustrative planned scope

Registration-entry concept: build two static screens to explore route understanding, excluding payments, accounts and live integrations. Functional check: route links reach the correct mock screen. Customer evidence: a later permitted uncoached task, with scope and source limits. Access pending; no actual test or product build exists.

Proceed means the bounded step recorded in Validate. Iterate or pause can require research/blocker resolution first; planning here is still useful but does not grant execution approval. Do not imply real automation or production readiness. No product is built by this worksheet.
